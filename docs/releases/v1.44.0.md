tapiOca is safer to run where the internet can reach it, and every release from now on passes a security test of over 1,100 checks before it's published.

## New

- **Security tests with every release.** Each one tries what an attacker would: every address tapiOca answers, asked as someone from the internet, a Kid, two Users and an Admin; made-up and ended sign-ins; paths that try to leave your folders; and requests that try to make tapiOca connect somewhere it shouldn't. `SECURITY.md` says what's tested, and the signs that a server was broken into.
- **A question before saving an address at home.** When you save a new alert address, or Sonarr's or Radarr's, that points to a device on your home network, the page asks "This points to a device on your home network. Save it?" first.
- **Where tapiOca connects,** listed in the README, with advice for a server that's reachable from the internet.

## Fixed

- **Plex's sign-in stays with Plex.** A file address from Plex that pointed somewhere else could have sent tapiOca's Plex sign-in there. tapiOca now plays only Plex's own file addresses.
- **An app's sign-in works only in an app,** and the page's only in a browser.
- **Every request tapiOca makes is checked first.** tapiOca never connects to a cloud server's private settings address, uses only http and https, and connects only to the addresses it checked, so a name can't change its answer partway. A slow name lookup gives up in time and never holds up playing.

## Updating

`tapioca-1.44.0.zip` is the source. Update the way the banner says, or see [Updating](https://github.com/egadgetboy/tapioca-server#updating). The database doesn't change, so tapiOca makes no copy.

## Rolling back

Use the image `ghcr.io/egadgetboy/tapioca-server:1.43.0` (see [Rolling back](https://github.com/egadgetboy/tapioca-server#rolling-back)). It runs on this database as it is, so there's nothing to put back and nothing is lost.

For developers: `python -m tools.security_suite` runs the tests and writes `docs/security/report-<version>.md`; `python -m tools.attack_check` still runs the live part alone.
