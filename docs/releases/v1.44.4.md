The update check finds new tapiOca releases again, and the filters in the "Needs you" list now match their counts.

## Fixed

- **The update check works again.** Since 1.44.2, it asked GitHub for tapiOca's releases by the number of the repository from before its fresh start, and GitHub answered that it couldn't find it. The log said "The update check couldn't tell whether a new tapiOca is out (GitHub answered 404)", and the page never offered an update. Now it asks for the repository by its current number, and tapiOca's own checks now make sure that number stays right. Nothing else it sends or keeps has changed.
- **The "Needs you" filters match their counts.** On the Broken files tab, problem reports from people also showed under **Missing** and **Broken or damaged**, and the **All** count left them out, so it didn't match the count beside "Needs you". Now reports show only under **All**, and the **All** count includes them, so the two counts match. **Broken or damaged** and **Missing** list files only.

## Updating

`tapioca-1.44.4.zip` is the source. Update the way the banner says, or see [Updating](https://github.com/egadgetboy/tapioca-server#updating). If your server is on 1.44.2 or 1.44.3, its update check can't see this release: update by hand, the way [Updating](https://github.com/egadgetboy/tapioca-server#updating) says. Nothing in the database changes.

## Rolling back

Use the image `ghcr.io/egadgetboy/tapioca-server:1.44.3` (see [Rolling back](https://github.com/egadgetboy/tapioca-server#rolling-back)). It runs on this database as it is, and nothing is lost. Its update check fails again until you update.
