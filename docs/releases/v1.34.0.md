tapiOca was called StationPlay until version 1.34.0. This release brings its new name, **tapiOca: Stations & Media**, and a ready-made image to install and update from. It adds Automatic subtitles, up to three alert addresses, an optional update check and Switch user.

## New

- **tapiOca.** A new name, logo, colors and fonts. tapiOca serves its fonts itself, never from the internet. Your stations, settings, people and Plex's tuner carry over as they are. Names and IDs other programs rely on stay as they were: the `stationplay` container, `stationplay.yaml`, the `stationplay.db` database, the cookies, and Plex's tuner and guide IDs (see `docs/notes/names-kept.md`). The new install setting has the new name: `TAPIOCA_INSTALL`.
- **A published image,** `ghcr.io/egadgetboy/tapioca-server`, for amd64 and arm64. Each release moves `:latest`, `:1.34` and `:1.34.0` only after that exact image's tests pass. If you built it from its zip, switch once: see [Switching to the published image](https://github.com/egadgetboy/tapioca-server#switching-to-the-published-image). Starting never needs the internet; updating fetches the new image.
- **The update check** (optional). If an Admin says yes, tapiOca asks GitHub once a day whether a newer version is out, and shows a banner with the steps for your kind of install (from `TAPIOCA_INSTALL`). GitHub sees your server's internet address when it asks. It asks nothing until an Admin answers.
- **Automatic subtitles.** With tapiOca's newer apps, subtitles in your language show when the sound is in another one, and stay off when the sound is yours. Each person can choose Automatic, On or Off.
- **Up to three alert addresses,** each with its own Test. Slack's and Discord's formats are used where they apply.
- **Switch user.** The PIN sign-in now says "Not Jo? Switch user", to sign in as someone else.
- **Where each person last signed in from** shows under the time on the **Access** tab. Sign-ins through tapiOca's public port are marked as such.
- **Signed releases.** Each release's zip and its `SHA256SUMS` are signed. `SHA256SUMS` lists each file's checksum and the image's digest (see [Checking a release's signature](https://github.com/egadgetboy/tapioca-server#checking-a-releases-signature)).

## Fixed

- Alerts on Discord show station names as written, with no link previews.
- Long lists and dialogs show an arrow when there's more below.
- An Admin who set a PIN sees **Change PIN**, not **Set PIN**.

## Updating

`tapioca-1.34.0.zip` is the source, `stationplay.yaml` is for TrueNAS SCALE, and `docker-compose.yml` is for everything else.

**From 1.33.1 or earlier, switch to the published image once:** follow [Switching to the published image](https://github.com/egadgetboy/tapioca-server#switching-to-the-published-image). Your stations, settings, sign-ins and Plex token are kept. tapiOca first saves `data/backups/before-1.34.0-<date>.db`, then adds where each person last signed in from. For a new install, see [Install](https://github.com/egadgetboy/tapioca-server#install).

## Rolling back

To go back to 1.33.1:

1. Stop tapiOca.
2. In the data folder, replace `stationplay.db` with `backups/before-1.34.0-<date>.db`, and delete `stationplay.db-wal` and `stationplay.db-shm` if they're there (see [Rolling back](https://github.com/egadgetboy/tapioca-server#rolling-back)).
3. Unzip `stationplay-1.33.1.zip`, from 1.33.1's release, in the folder that holds `src` (it unzips to `src`).
4. With a YAML or compose file, put back 1.33.1's `build:` block and `image: stationplay:1.33.1` (from its `stationplay.yaml` or `docker-compose.yml`) in place of `image:` and `pull_policy:`. Then save the app in TrueNAS, or run `docker compose up -d --build` (with `sudo` over SSH on Synology).
5. With docker run, run `docker build -t stationplay:1.33.1 ./src`, then `docker rm -f stationplay`, then your `docker run` command with `stationplay:1.33.1` at the end.

Your stations and settings are kept, apart from changes made since the update.
