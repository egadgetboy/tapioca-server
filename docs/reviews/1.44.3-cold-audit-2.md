# Cold audit 2: tapiOca server 1.44.3, "Sign out always takes you off the list"

The final-diff audit, the second of the release's two cold audits, by an
independent auditor who didn't build it (October 29, 2026). It re-checks
each SO-C1 item and audits the whole diff fresh. Its report as given, then
what was done about each finding.

**What it read.** `wip/signout-ends`, `33cacfc..9c8f940`: twelve commits,
four since the first audit (`8b7d6a8`, `6655a55`, `5c194f6`, `9c8f940`); the
server's `docs/threat-models/signout-ends.md`; the audited record in the
apps' repository with its three design audits; the first audit's report; the
plan's DL391. Probes ran in scratch worktrees, removed after; neither
checkout was changed.

**What it ran (observed):** the requested pytest set (682 passed);
`tools.attack_check` (825 of 825); `upgrade_check --from v1.44.2` (114
passed); `tools/image_check.py` (**1 failed**, 518 passed: SO-C2-01); ruff
on `app/` and the changed tests and tools (clean); the gates' changed-line
ruff with C901 and `vulture app --min-confidence 80` (none); `dupes.py`,
`size_ratchet.py` and `claude_rules.py` (pass); `test_info_station.py` (22
passed); the race tests and the newest tests 20 times each (no failure); the
final test file on `573db0f`'s code (66 failed, 13 passed: the 13 are the
rows that answer the same before and after); five mutations; a performance
probe to 50,000 sessions; the signature steps, with throwaway keys and with
the published 1.44.2 `SHA256SUMS`.

## Verdict

**No P0. One P1 (SO-C2-01): the image's own tests fail, so CI won't publish
1.44.3 as it is.** The code does what the design says on every path tried;
no probe could take another person off a list, keep an ended sign-in alive,
or reach anything else through the opened route. Two of the record's rules
have no test that would notice if they broke (SO-C2-02, -03), and the census
can be slipped past (SO-C2-04). **1.44.3 may be released once SO-C2-01 is
fixed and `tools/image_check.py` passes**, with SO-C2-02 to -04 in the same
round.

## Findings

### SO-C2-01 (P1, release gate): `gates.yml` isn't in the image, so the image's tests fail

`8e4d459` changed the Dockerfile to copy every workflow, but `.dockerignore`
leaves out `.github/` and brings back only `release.yml` and `image.yml`, so
`test_the_checks_own_tests_print_as_text` fails in the image (observed), on
both architectures, and nothing publishes. **Fix:** bring back
`.github/workflows/gates.yml` in `.dockerignore`; run `image_check` again.

### SO-C2-02 (P2, proof): no test reaches the ended path's list check (§3 rule 1, P18)

Cutting the list check left every test passing (observed): P18's test passes
because `_take_off` already forgot the row. A row whose person is off the
list does exist when an Admin chooses that device for them (which lists no
one), or after R3. **Fix:** a test: Pat signs in on the TV, his password is
changed on the phone, an Admin chooses the TV for him, and the ended remove
answers 401 with the Admin's choice kept.

### SO-C2-03 (P2, proof): rule 3 isn't tested where it matters

A mutation making `_take_off` end every sign-in on the device survived
(observed). P8's test checks the list, not the sign-in of Ada, on the TV now.
**Fix:** in P8, and in P1b with someone else on the TV, assert the other
person's sign-in still works.

### SO-C2-04 (P2, census): the census skips a function's first statement of any kind, and can't see a name built at run time

Its docstring skip took any first expression statement, so a method whose
first statement reads the table, and a module that builds the name at run
time, both passed (observed). **Fix:** skip only a string constant; add a
run-time check (an authorizer on the connections, recording which function
touches the table); move the census into `tests/security`.

### SO-C2-05 (P3, the README and the retired key)

1. "Public releases here start with 1.32.0": `release.yml` says 1.44.2.
2. The overview names 1.44.2, though this README ships in 1.44.3.
3. In the table of what the apps gain, 1.36.0's row came after 1.37.0's.
4. "Vouches for 1.44.2 alone" holds only by the reader's choice of `-I`:
   `-I tapioca-release-1.44.2` accepts any file that key signs, whatever its
   version, and the key can sign until the archive's secret is deleted.
   **Fix:** don't trust the retired key at all: pin 1.44.2's `SHA256SUMS`
   digest in the README (or sign it again with the new key); correct DL391.
5. The rollback example names `:1.44.1`; for someone on 1.44.3 it's 1.44.2.

Otherwise the README passed what was asked: Station, Media, PIN, tapiOca's
casing, no real network or show names and no IPTV, every link inside the
page resolves, and the install steps match the files.

### SO-C2-06 (P3, the record)

Sound: the dropped column, the census by name (but see SO-C2-04), the
restore forgetting rows (stronger than the audited record), P7's network
case moved to P20, and P21's parenthetical. Not said plainly: P21's §7
bullet contradicts §4; "the TV asked first" lost "common, not rare" and why;
the restart-loop bullet overstates (a start that fails before serving
changes no sign-in, so each rebuild makes the same rows; what's real is the
extra copies) and contradicts "harmless"; "later versions add columns" needs
"nullable or with a default"; rule 5 and FG-03 need "before-update copies
aside"; FG-07's update runs at every sign-in's "seen"; the screen is "Who's
tuning in?" in the server's own words; and the census isn't in the security
suite, so the corpus doesn't guard it.

### SO-C2-07 (P3, tests)

1. P21's "record unchanged" compared `[]` with `[]`: put a row elsewhere first.
2. The 27-case agreement test compared all of `changes_needed`: compare only
   the record's lines, so an unrelated line can't make it pass.
3. SO-C1-10's process only partly met: on `573db0f`, P21's and the restore's
   tests fail at the missing table, not the behavior (the restore's shown
   right by mutation).
4. The handler's `HTTPException(*state["token_refused"])` relies on the Gate
   always refusing an API token there: make the coupling plain.

### SO-C2-08 (P3, process): what isn't in the diff wasn't audited

The notes, the gate's manifest and the soak. When the notes are written, name
the key change, and say plainly the case that remains: if the app went back
to Who's tuning in? on its own before Sign out, the person is still listed,
and they pick themselves and sign out.

P13); "renewed from" stops once the new sign-in is seen; the start's check
stays quiet in normal use; the backup and the rebuild agree; the restore is
safe; the opened route keeps its guards; the signature steps work.

owner's deletion of the archived secret, older images on the registry.

## Quality bar

swallowed errors or retries that hide a bug, no narrating comments, no
one-user abstractions, small functions): `dupes.py`, `size_ratchet.py`,
`claude_rules.py`, vulture and the changed-line ruff with C901 all pass, and
`app/main.py` doesn't grow. What it found against the bar is SO-C2-04's
census and SO-C2-07's coupling, both below.
